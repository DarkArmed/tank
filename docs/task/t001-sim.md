# t001 对战逻辑

对应需求：p001

技术设计：`docs/DESIGN.md`

状态：已实施并完成自动验证；等待用户手动验证

## 目标

实现当前 `01→14` 里程碑的纯逻辑模拟层和自动测试，不包含绘制与发布地图数据。

## 范围

- 只修改 `frontend/src/sim/`，排除 `frontend/src/sim/maps/`。
- 实现 DESIGN 规定的模拟公开接口、固定 tick、确定性随机、状态投影和事件输出。
- 实现 p001 当前里程碑中的移动、碰撞、射击、地形、玩家防护、道具、敌人、AI、计分、复活、借命和三关状态机。
- 实现并测试 BI-01～BI-21 的当前采用规则。
- 实现地图加载和校验；t003 未完成时只在测试中使用合法的最小内嵌地图。
- 接入 t003 后支持第 1～3 关连续推进。

## 不包含

- 菜单、输入设备、Canvas、音频和其它应用壳功能。
- 发布用地图内容。
- `15→28`、敌人拾取道具、建造模式或第 4 关以后内容。
- 修改 p001 未确认的玩法规则或 DESIGN 的公共契约。

## 依赖

- p001 当前里程碑需求。
- `docs/DESIGN.md`。
- 最终三关集成依赖 t003，但实现工作不依赖 t003。
- t004 未完成时按 p001 的“预设待验证”规则开发；t004 的未来结果只有经用户确认并更新 p001 后才改变本 Task。

## 涉及模块

- `frontend/src/sim/`
- 读取 `frontend/src/sim/maps/`，但不修改其内容。

## 验收标准

- 公开 API、状态、事件、地图校验和依赖方向符合 DESIGN。
- 重要玩法与边界均有 Vitest 覆盖，尤其是 BI-01～BI-21、同 tick 优先级和双人借命。
- 相同 seed、地图和输入产生相同快照与事件序列。
- 实体数组顺序不影响同 tick 的伤害、计分和胜负。
- 使用测试地图可以完整打完一关；接入 t003 后可以连续完成三关。
- 不修改 t002、t003 的写入范围。

## 验证方式

1. 运行模拟层 Targeted Vitest。
2. 运行前端全部 Vitest 和 TypeScript Compiler。
3. 使用固定 seed 重放同一输入序列并比较结果。
4. 接入 t003 后验证三关加载、切换和最终完成事件。
