# t003 五张地图数据

对应：p001

## 目标

提供第一版 5 张可发布的 13×13 地图 JSON。只做数据，不做规则、不做画面。

## 范围

- 目录仅限：`frontend/src/sim/maps/`。
- 文件：`stage-1.json` … `stage-5.json`。
- 布局互异；五张合计覆盖：空地、砖、钢板、草、冰、河、总部砖围。
- 出生点符合 p001 第 4.1 节：总部底中；1P 左、2P 右；敌人左上 / 顶中 / 右上（可用约定格，或由固定坐标推导，但 JSON 里必须能读出 13×13 地形）。
- Schema 冻结如下，t001 只读不改：

```json
{
  "id": 1,
  "width": 13,
  "height": 13,
  "tiles": [
    ["empty", "brick", "steel", "grass", "ice", "water", "hq"]
  ]
}
```

- `tiles` 为 13 行 × 13 列；行从上到下，列从左到右。
- `hq` 只出现在底部中央及其初始砖围所需格子；不得另发明新地形字符串。
- 半格破坏不在 JSON 里预拆，由 t001 运行时拆分。

## 不包含

- `createGame` / `tick` / AI / 道具。
- React、Canvas、Vite 配置。
- 第 6 张及以后地图。

## 依赖

无。可与 t001、t002 并行。

## 涉及模块

`frontend/src/sim/maps/**`

## 验收标准

- 恰好 5 个 JSON，均可按上述 schema 解析。
- 每张 13×13；至少 1 张含草、冰、河、钢。
- 总部区域可识别；不出现未定义 tile 名。
- 不修改 t001、t002 文件。

## 验证方式

- 用 JSON schema / 简单脚本或测试断言 5 个文件合法（可由 t001 的加载测试复用，但本 Task 本身至少保证文件存在且结构正确）。
