# t002 FC 像素应用壳与输入

对应需求：p001

技术设计：`docs/DESIGN.md`

状态：未分配

## 目标

建立浏览器前端工程，实现菜单、输入、固定步长循环、Canvas 绘制和原创 8 位风格音效，并接入模拟层。

## 范围

- 修改 `frontend/` 中除 `frontend/src/sim/` 以外的文件。
- 建立 React、TypeScript、Vite、Vitest 工程。
- 实现玩法选择页、人数选择页、CONSTRUCTION 无响应、第一阶段 SELECT 无响应。
- 实现键盘、标准 Gamepad 和常见 USB FC 控制器适配及 1P/2P 设备分配。
- 实现手动暂停、失焦暂停、控制器断开暂停和恢复。
- 实现固定步长调度、Canvas 256×240 整数倍绘制、HUD 和场景提示。
- 根据模拟事件使用 Web Audio API 合成原创音效。
- t001 未就绪时可以使用 DESIGN 允许的最小 stub；最终集成时删除。

## 不包含

- 战斗规则、AI、碰撞、计分或地图数据。
- `15→28`、敌人拾取道具或建造模式。
- 原作字体、贴图、音频、ROM 或录像。
- 修改模拟层公开接口。

## 依赖

- p001 当前里程碑需求。
- `docs/DESIGN.md`。
- 最终端到端验证依赖 t001、t003。

## 涉及模块

- `frontend/`，排除 `frontend/src/sim/`。

## 验收标准

- A～N 均可选择，随后可选择 1P、2P 或 CONSTRUCTION。
- CONSTRUCTION 确认无动作；SELECT 不切换到第二组。
- 单人和双人设备规则、暂停与断线行为符合 p001。
- 画面内部为 256×240，只做整数倍邻近放大。
- 绘制只读取快照，音频只读取模拟事件，不复制战斗规则。
- 接入 t001、t003 后可完成标题到战斗、过关或失败的真实流程。
- 不修改 t001、t003 的写入范围。

## 验证方式

1. 运行输入、菜单、循环、绘制和音频 Targeted Vitest。
2. 运行 TypeScript Compiler、全部 Vitest 和 Vite 生产构建。
3. 在当前稳定版桌面 Chrome、Edge 中目视验证缩放和控制器流程。
4. 最终集成后实玩单人流程，并使用两个控制器验证双人开始和同时操作。
