## 4. 通用实验方法

1. 先按录像客观记录结果，再查看并填写“与预设规则”字段，避免为了匹配预设而解释画面。
2. 一次只改变一个条件，例如只改变火力等级，保持射击方向、距离和目标状态一致。
3. 射击前至少保留一段能辨认玩家状态、目标完整状态和周边地形的画面。
4. 尽量正对目标中心射击；测试边缘命中时单独标记，不与中心命中合并。
5. 每发子弹分别记录命中前、命中、命中后的画面，不能只凭爆炸动画推断结果。
6. 地形测试要记录被击中的 8×8 半格或可辨认的局部形状。
7. 装甲和防护测试要记录命中前后的颜色、外观、生命和携带状态。
8. 无法构造严格同时命中时标记“未复现”，不得用先后相近的两次命中代替。
9. 每个确定性结果至少重复 3 次；发现模式、关卡或玩家人数会改变结果时拆分记录。

## 5. 实验分组

### 5.0 推荐逐项执行顺序

以下顺序只用于减少重开、拾取道具和双人布置次数，不代表规则优先级，也不预设观察结果。若某个条件暂时无法构造，先标记“未复现原因”并继续后项，不用推测补齐。

| 顺序 | 项目 | 推荐前置与复用方式 | 本项必须特别记录 |
| ---: | --- | --- | --- |
| 1 | BI-17 战场边界 | 单人基础状态；依次测试上、右、下、左，可作为录像/帧步进校准 | 四方向各自的最后可见帧、消失帧、贴边目标和命中特效 |
| 2 | BI-07 河流 | 保持基础火力；找一条能看到河后目标的直线 | 子弹进入、经过、离开河面的帧，河面和后方目标状态 |
| 3 | BI-05 不可消草 | 仍用未经证实有消草能力的基础状态 | 草前、草中、草后的子弹位置及草半格状态 |
| 4 | BI-01 普通弹打砖 | 复用同一基础坦克和完整砖墙，四方向中心命中后再测边缘 | 每发破坏的具体 8×8 半格、完全打通发数、子弹结果 |
| 5 | BI-03 普通弹打钢 | 复用基础坦克；玩家普通弹与普通敌弹分开记录 | 钢板前后半格状态及子弹结果，不把未损坏推成能力定义 |
| 6 | BI-09 无装甲敌人 | 同一局寻找外观可辨认且前置状态清晰的目标 | 命中前外观、击毁帧、子弹、分数和掉宝情况 |
| 7 | BI-14 敌弹命中敌人 | 同一局利用敌人射线布置；若无法稳定构造先标未复现 | 是穿过、阻挡还是造成变化；出生状态另开子条件 |
| 8 | BI-16 子弹命中道具 | 出现位置适合的道具时顺带测试；玩家弹、敌弹分开 | 道具和子弹各自前后状态，不能仅凭道具仍在推断未接触 |
| 9 | BI-08 子弹命中总部 | 放在基础局末尾，玩家弹和敌弹分别测试并重开 | 命中帧、总部、子弹、场景变化；最后敌人已清空时另开实验 |
| 10 | 枪-01 第一把枪 | 新坦克从基础火力开始，先录拾取前后，不立即让其受击 | 火力、枪次数、枪护甲、消草能力和外观的客观变化 |
| 11 | BI-02 高火力弹打砖 | 复用已确认具备相应火力表现的坦克，重复 BI-01 的位置和方向 | 与 BI-01 相同字段，不能仅以“第一把枪”代替能力证据 |
| 12 | BI-04 可打钢弹打钢 | 复用上一步坦克；先用实际破钢表现确认条件 | 每发破坏范围、完全打通发数、子弹结果 |
| 13 | 枪-02 第二把枪 | 保持同一辆坦克，记录第二次拾取前后 | 火力、枪次数、枪护甲、消草能力和外观 |
| 14 | BI-06 可消草弹打草 | 复用已观察到对应能力的坦克 | 每个经过位置的草半格和子弹连续帧 |
| 15 | 枪-03 第三把及以后 | 继续同一辆坦克，至少记录第三次拾取 | 枪次数是否变化、火力、护甲、消草能力、道具分数 |
| 16 | BI-10 装甲敌人 | 保留高火力状态；无装甲与多层装甲目标分别逐发命中 | 每发后的颜色/外观/层数迹象，闪光出宝时点和最终击毁 |
| 17 | BI-12 无敌玩家 | 可先利用新生无敌，再另测钢盔无敌 | 命中效果、子弹结果，以及船/枪/火力保护是否被消耗 |
| 18 | BI-11 无保护玩家 | 在确认无无敌、船、枪护甲或高火力保护后测试 | 当前坦克被毁、生命/复活/离场时间线和子弹结果 |
| 19 | 枪-04 护甲消耗后再拾枪 | 构造只有枪相关状态并受击，再拾取一把枪 | 受击前后与再拾取前后的火力、枪次数、护甲和消草能力 |
| 20 | BI-18 船防护 | 先在陆地受击，再另局或另次在河面受击 | 船是否消失、坦克是否存活；河面后续行为交给船-边界实验 |
| 21 | 船-边界 | 船在河面受击后，先在当前连通河面移动，再上岸并尝试重新入河 | 每段路径的起止时间点、是否可移动/上岸/重新入河 |
| 22 | BI-19 多重保护 | 从可辨认的单层保护开始，再构造枪+火力、船+枪+火力 | 每一发究竟消耗哪项保护；状态不清时不得推断顺序 |
| 23 | BI-13 玩家弹命中队友 | 切到双人；普通状态先测，出生保护状态另开子条件 | 子弹是否穿过/消失，队友伤害、定身、装备变化 |
| 24 | BI-15 子弹互撞 | 先双人玩家弹迎面，再测玩家/敌人、追尾和垂直交叉 | 每发子弹的逐帧位置；只有确认同帧接触才提升证据等级 |
| 25 | BI-21 多弹同目标 | 复用双人布置，先选耐受多发的地形/装甲目标，再测玩家 | 两发各自命中帧、目标逐帧状态、累计伤害和溢出情况 |
| 26 | BI-20 最后敌人与总部同帧 | 最后执行，需预留最后一敌并布置另一发命中总部 | 两处命中必须有同帧依据；总部、敌人数、场景和全部子弹状态 |

### 5.1 地形与边界：BI-01～BI-08、BI-17

#### 砖墙：BI-01、BI-02

1. 找到完整砖墙，分别从上、下、左、右正对中心射击。
2. 用普通火力逐发射击，记录每发后砖墙形状和需要几发完全打通。
3. 用“对砖更强”的火力重复相同位置与方向。
4. 每发记录子弹在命中后是否消失、是否能在同一次命中影响多个半格。
5. 额外测试命中砖墙边缘或两个半格交界处，单独记录结果。

#### 钢板：BI-03、BI-04

1. 用无打钢能力的玩家子弹和普通敌弹分别射击完整钢板。
2. 用玩家普通火力和可打钢火力分别测试；当前 `01→14` 不以敌人吃道具构造测试条件。
3. 记录每发破坏范围、完全打通所需发数和子弹是否消失。

#### 草、河和总部：BI-05～BI-08

1. 分别用不可消草和可消草火力射击完整草地，记录草的变化和子弹是否继续。
2. 隔着河射击可见目标，确认子弹是否无变化通过河面。
3. 分别验证玩家子弹和敌弹命中总部的结果。
4. 清掉最后一个敌人后，在仍能操作或仍有子弹时验证总部是否继续可被毁。

#### 战场边界：BI-17

1. 从四个方向向边界射击。
2. 记录子弹在哪一帧、什么位置消失，是否出现爆炸或影响贴边目标。

### 5.2 坦克与防护：BI-09～BI-14、BI-18、BI-19

#### 敌人装甲：BI-09、BI-10

1. 分别选择可一击敌人和明显有多层装甲的敌人。
2. 逐发射击，记录每次命中后的颜色、闪光状态、外观和是否掉宝。
3. 记录每发削减的实际层数以及最后一发的子弹结果。
4. 闪光敌人需要区分“命中即出宝”和“击毁才出宝”。

#### 玩家受击：BI-11、BI-12、BI-18、BI-19

分别构造以下状态并让一发敌弹命中：

- 无任何保护。
- 出生无敌或钢盔无敌。
- 只有船。
- 只有枪抵挡。
- 只有 ≥4 火力抵挡。
- 枪抵挡与 ≥4 火力抵挡同时存在。
- 船、枪抵挡与 ≥4 火力抵挡同时存在。

附加记录以下装备边界，不把观察结果自动写成项目规则：

- 基础火力状态下连续拾取第一、第二和第三把枪，记录火力、枪护甲和消草能力变化。
- 枪护甲被消耗后再次拾取枪，记录火力和护甲是否恢复。
- 船在陆地和河面分别被命中，记录船消失后坦克是否存活、能否继续在当前河面移动及离开陆地后能否重新入河。

每次记录子弹是否消失、具体消耗了哪一层保护、玩家火力/外观/生命变化以及是否立即复活。

#### 同阵营目标：BI-13、BI-14

1. 双人模式下让 1P 子弹正面穿过 2P，记录子弹与 2P 状态。
2. 设法让敌弹命中另一辆敌人；记录穿过、阻挡、伤害或无法复现。
3. 若出生保护中的坦克表现不同，单独记录，不与普通状态合并。

### 5.3 子弹、道具和同时事件：BI-15、BI-16、BI-20、BI-21

#### 子弹互撞：BI-15

分别测试：

- 玩家弹与敌弹迎面相撞。
- 两名玩家的子弹迎面相撞。
- 两发子弹同向追尾。
- 两发子弹垂直交叉。

必须用逐帧证据确认是否在同一位置和同一帧发生接触；否则只能记为 C 级线索。

#### 子弹与道具：BI-16

1. 等待道具出现在可直线射击的位置。
2. 分别用玩家弹和敌弹命中。
3. 记录道具是否保留、消失、被阻挡，以及子弹是否继续。

#### 同时结算：BI-20、BI-21

1. 尝试让玩家子弹击毁最后一个敌人的同一帧，另一发子弹命中总部。
2. 尝试让两发子弹在同一帧命中同一装甲目标、玩家或地形半格。
3. 只有逐帧证据能确认“同一帧”；无法稳定复现时保留待验证。
4. 记录场景、击毁数、总部、生命、装甲和两发子弹最终状态。

## 6. 结果汇总

完成一组实验后，在 p001 对应 BI 行填写简洁、可实施的原作观察，例如：

```text
每发普通子弹破坏命中方向的一个半格，子弹消失；四方向各重复 3 次一致。证据 A，录像 bc-brick-01 00:12–00:31。
```

不要在“原作实机结果”中写推测或实现方案。若不同模式结果不同，分别列出。

用户随后对每一项选择：

- 与原作一致。
- 采用更简单的项目规则。
- 保留现有 p001 规则。
- 继续验证。

确认后再更新 p001 的“本项目当前采用规则”和状态。

## 验收标准

- BI-01～BI-21 每项都有 A/B 级观察结果，或明确标为“未复现”并说明原因。
- 所有结论能追溯到版本、模式、重复次数和仓库外录像时间点。
- 随机或不一致结果没有被强行概括为确定规则。
- p001 只更新原作观察；项目采用规则的变化均经过用户逐项确认。
- 仓库中没有 ROM、反汇编代码、录像或原版素材。

## 验证方式

1. 用户提交填写后的实验记录或逐项结论。
2. Agent 检查每个 BI 编号是否有证据等级、重复次数和明确观察。
3. 用户逐项确认本项目采用规则。
4. Agent 更新 p001 状态并再次检查需求矩阵是否无歧义。
5. t004 在用户确认后才标记为最终完成。
